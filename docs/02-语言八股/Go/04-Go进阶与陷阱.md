# 04 · Go 进阶与陷阱八股

## 一、反射

### 是什么
- reflect 包在运行时检查类型和值：TypeOf、ValueOf；可以读字段、调方法、动态创建。
- 三大定律（背）：
  1. 反射可以从接口值得到反射对象。
  2. 反射对象可以还原成接口值。
  3. 要修改反射对象，值必须是可写的（取指针：ValueOf(&x).Elem()）。

### 性能
- 反射很慢（动态派发、无法内联、涉及逃逸），热点路径避免；JSON 序列化、ORM、依赖注入才用。
- 高性能替代：代码生成（easyjson、gqlgen）、类型断言后直接操作。

### 应用
- encoding/json 根据 tag 序列化、ORM 映射、测试断言库、配置注入。

## 二、标准库常考点

### net/http
- ServeMux 路由；Handler 接口 = ServeHTTP(w, r)。
- 中间件模式：Handler 包 Handler（洋葱模型）：
```go
func Logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        log.Println(r.URL.Path)
        next.ServeHTTP(w, r)
    })
}
```
- 注意：http.Server 要设置 ReadTimeout/WriteTimeout/IdleTimeout，防慢客户端耗尽连接。
- 并发模型：每个连接一个 goroutine（net/http 是并发安全的）。

### JSON
- 结构体 tag：json:"name,omitempty"；字段首字母大写才导出。
- 反序列化用指针；用 map[string]any 丢失类型，能不用就不用。
- 大 JSON 用 json.Decoder 流式；性能敏感用 easyjson。

### 时间与字符串
- time.Time 比较用 Before/After/Equal，别用 ==；格式化用固定模板 "2006-01-02 15:04:05"。
- strconv（Atoi/Itoa）比 fmt 快得多；strings.Builder 拼串。

## 三、性能优化清单（场景题）

1. 先 profile 再优化：pprof / benchmark（go test -bench）。
2. 减少内存分配：预分配 make([]T, 0, n)、复用对象（sync.Pool）、避免接口装箱逃逸。
3. 字符串拼接：strings.Builder；byte 操作用 []byte 少转 string。
4. 循环优化：把 len()/方法调用提出循环；局部变量避免重复 deref。
5. 并发：IO 密集用 goroutine + channel/errgroup；CPU 密集用 runtime.GOMAXPROCS 匹配核数。
6. 避免锁竞争：用 atomic 计数、分片（sharded map）、RWMutex 读多写少。
7. 序列化：JSON 换 protobuf/gob；压缩传输。
8. 数据库：连接池参数（MaxOpenConns/MaxIdleConns/ConnMaxLifetime）、批量插入、索引。
9. sync.Pool 适用：高频临时对象（buffer、struct），注意 GC 会清空。

## 四、常见坑合集（必背）

1. **循环变量捕获**（Go 1.21 之前，高频）：
```go
var funcs []func()
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { fmt.Println(i) })  // 1.22 前输出 3 3 3
}
```
- 解决：`i := i` 局部拷贝；Go 1.22 起 for 循环变量每次迭代是新变量（已修复）。
2. **map 并发写崩**：用锁或 sync.Map。
3. **slice 共享底层数组写穿**：见基础篇；用 copy 或限制 cap。
4. **defer 参数立即求值**：`defer file.Close()` 没问题；`defer log(读到的状态)` 要闭包。
5. **接口 nil 判断**：typed nil 装入接口 != nil。
6. **channel 重复 close / 向 closed 发送** → panic；**关闭的 channel 读零值** → 用 ok。
7. **goroutine 泄漏**：无 ctx/超时的阻塞等待。
8. **range 复制**：`for _, v := range slice` 里 v 是副本；对大结构体用下标或指针避免拷贝。
9. **range map 无序**：要排序先取 key 排序。
10. **int 溢出**：time.Duration 等运算注意单位（纳秒）；用 math/big 或检查。
11. **错误处理**：吞错 `_`、defer 里 Close 忽略错误、panic 当业务异常。
12. **time 比较**：== 比较的是瞬间+地点等内部字段，用 Equal。
13. **初始化顺序**：包级变量依赖、init() 顺序（按依赖、按文件名字母序）别写有副作用的 init。
14. **锁复制**：sync.Mutex 不能复制（拷贝后锁不共享）——结构体值传递含锁要小心。
15. **defer 循环里累积**：大量 defer 堆积（延迟到函数结束），循环内注意作用域。

## 五、Go 1.x 新特性速览（体现更新）

- 1.18：泛型（type parameter）、Fuzz 测试。
- 1.19+：atomic 类型、slices/maps 标准包。
- 1.20/1.21：errors.Join、slices.Sort 泛型排序、min/max 内建。
- 1.21：循环变量每次迭代新变量（闭包坑修复，默认开启）。
- 1.22：for range 整型（for i := range 10）、http.ServeMux 增强（方法+通配符路由）。
- 1.23：迭代器（iter.Seq）、range over func。
- 关注点：面试提"我关注 Go 版本演进，比如 1.21 修了循环变量、1.22 路由增强"，是加分项。

## 六、测试与工程化

- go test：Test 前缀函数、表驱动测试（table-driven）、t.Run 子测试。
- benchmark：Benchmark 前缀，`go test -bench=. -benchmem`。

- go vet 静态检查；golangci-lint。

## 七、常问追问

1. 反射为什么慢？→ 动态派发、无法内联、逃逸、无编译期优化。
2. 循环变量闭包坑怎么修？→ i:=i；或升级 Go 1.22。
3. sync.Pool 什么时候用？→ 高频创建销毁的临时对象；GC 会清空，别放常驻状态。
4. 为什么 time.Time 不能 ==？→ 内部含墙钟/单调钟字段；用 Equal。
5. 中间件怎么实现？→ Handler 嵌套，洋葱模型。
6. JSON 反序列化到空接口有什么问题？→ 数字变 float64、丢失结构信息。
7. 怎么做优雅退出？→ signal.NotifyContext → cancel → errgroup.Wait。
8. 为什么不要用 panic 做业务错误？→ 崩溃不可控、不能跨 goroutine 恢复；用 error。
9. Go 泛型有什么限制？→ 类型约束（constraints）、不能用于方法（仅函数和类型）、性能可能略降。
10. 线上 CPU 飙高怎么排查？→ pprof CPU profile 30s，看火焰图热点函数。

# 02 · Go 并发八股（重头戏）

## 一、goroutine（协程）

### 是什么
- 用户态轻量线程，由 Go runtime 调度，不依赖操作系统线程数。
- 初始栈约 2KB（1.4 前 4KB，1.4+ 2KB），按需增长到最大 1GB（64 位）。
- 一个 goroutine 约几 KB 内存，所以可以开几十万上百万个。

### 为什么轻
- 栈小且可动态扩缩；切换在用户态（runtime 调度），不经过内核；没有线程创建的昂贵资源（独立内核栈/上下文）。
- 对应关系：M（线程）与 G（goroutine）多对多，阻塞时 G 让出 M。

## 二、channel（必考）

### 基本
- channel 是 goroutine 间通信的管道（引用类型，make 创建，分无缓冲/有缓冲）。
```go
ch := make(chan int)        // 无缓冲：收发必须同时就绪，否则阻塞
ch2 := make(chan int, 10)   // 有缓冲：缓冲满才阻塞写，空才阻塞读
```

### 收发规则（背）
- 无缓冲：发送阻塞直到有接收者；接收阻塞直到有发送者（同步）。
- 有缓冲：缓冲未满发送不阻塞；未空接收不阻塞。
- 向已关闭的 channel 发送 → panic。
- 从已关闭的 channel 接收：缓冲区读完返回零值，`v, ok := <-ch` 中 ok=false 表示已关闭。
- 重复关闭 channel → panic。
- 关闭后继续读会一直得到零值（要配合 ok 或 range 判断结束）。
- nil channel：发送和接收都会永久阻塞（select 里可用来"禁用"分支）。
- 单向 channel：`<-chan T`（只读）、`chan<- T`（只写），用于函数签名约束。

### 使用模式
- 生产者-消费者 / worker pool：固定 N 个 goroutine 从 channel 取任务。
- 关闭通知：`close(done)` 广播给所有接收方（for range 结束）。
- 不要"关闭由接收方做"——惯例：只有发送方才能关闭。
- 同步等待完成：无缓冲 channel 或 WaitGroup。

## 三、select（必考）

- select 同时监听多个 channel，任一就绪即执行；多个就绪时**随机**选一个。
- default 分支：所有 channel 都阻塞时立即执行（非阻塞尝试）。
```go
select {
case v := <-ch1:
case ch2 <- v:
case <-time.After(3 * time.Second):   // 超时
default:
}
```
- 经典应用：超时控制、限流、多路复用、优雅退出。

## 四、sync 包（必考）

### Mutex / RWMutex
- Mutex：互斥锁，Lock/Unlock；不可重入（重复 Lock 死锁）。
- RWMutex：读锁可共享（RLock/RUnlock），写锁互斥（Lock/Unlock）；读多写少场景。
- 注意：RWMutex 写锁优先于新读锁（防止写饥饿）。
- 锁的粒度越大并发越差；用 defer Unlock 防止忘解锁。

### WaitGroup
- Add(n) → Done() → Wait()；计数归零前 Wait 阻塞。
- 坑：Add 必须在 goroutine 启动前调用；Done 次数不能超过 Add，否则 panic（负数计数）。

### Once
- `sync.Once` 保证函数只执行一次（并发安全），实现单例/懒初始化。
- 内部：原子 flag + 双重检查 + Mutex。

### atomic
- 原子操作：AddInt64、CompareAndSwap、Load/Store、Swap。
- 性能远高于 Mutex，适合计数器、标志位。
- CAS 失败要循环重试（自旋）。

### 并发安全原则
- "不要通过共享内存来通信，而要通过通信来共享内存"（用 channel 传数据）。
- 共享变量 + 多 goroutine 读写 = 数据竞争 → `go run -race` 检测。

## 五、GMP 调度模型（必考，讲清楚就行）

### 概念
- G：goroutine（协程）
- M：Machine，操作系统线程
- P：Processor，逻辑处理器，持有本地可运行 G 队列（容量 256）和当前正在执行的 G；数量默认 = CPU 核数（GOMAXPROCS 可调）

### 工作流程
1. 创建 goroutine 优先放当前 P 的本地队列；满了放全局队列。
2. M 从本地队列取 G 执行；本地空了去全局队列取；全局也空就**偷取**其他 P 队列的一半（work stealing）。
3. G 阻塞（channel/系统调用）时，M 会与 P 解绑：syscall 阻塞的 M 让出 P，P 挂到别的 M 上继续执行别的 G（handoff）；syscall 结束 G 回到队列。
4. sysmon 监控线程：检查长期运行的 G（>10ms 触发抢占）、GC 等。

### 为什么有 P
- 把"线程"和"协程"解耦：M 阻塞不影响全局调度；本地队列减少锁竞争（每 P 一个本地队列）。

### GOMAXPROCS
- 控制并行执行的线程数（P 数量）；CPU 密集任务设为核数即可，别盲目调大（增加切换和锁竞争）。
- 容器环境注意：Go 1.5+ 默认按 CPU 核数，容器限核不准时用 GOMAXPROCS 或 automaxprocs 库。

## 六、context（必考）

### 是什么
- 跨 API 和 goroutine 传递取消信号、超时、截止时间和元数据。

### 用法
```go
ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
defer cancel()
```
- WithCancel / WithTimeout / WithDeadline：取消或超时后 ctx.Done() 关闭。
- WithValue：传元数据（不要传关键参数，键用自定义类型避免冲突）。
- 传递规则：把 ctx 作为第一个参数显式传，不存结构体。

### 典型场景
- HTTP 请求取消：客户端断开 → 服务端 ctx 取消 → 下游调用终止，防止 goroutine 泄漏。
- 数据库/网络调用传 ctx；超时自动取消。

### goroutine 泄漏（重点）
- 起 goroutine 不退出：阻塞在 channel、for 死循环不查 ctx。
- 正确姿势：goroutine 里 select 监听 ctx.Done()，超时/取消主动退出。

## 七、并发模式（背几个）

1. Worker Pool：N 个 worker 从任务 channel 消费，结果写结果 channel。
2. Fan-in：多个 goroutine 输出合并到一个 channel（多个 goroutine 写同一 channel 是安全的）。
3. Fan-out：一个 channel 分发给多个消费者。
4. 管道 pipeline：每个阶段一个 goroutine + channel 连接，数据流式处理。
5. 错误传播：用 errgroup（golang.org/x/sync/errgroup）：第一个错误取消整个组。

## 八、常问追问

1. goroutine 和线程区别？→ 用户态调度、栈小可扩、成本低、量大。
2. 无缓冲和有缓冲 channel 区别？→ 同步交接 vs 异步队列。
3. 向已关闭 channel 发送会怎样？→ panic。
4. select 多个 case 就绪怎么选？→ 随机。
5. Mutex 可以重入吗？→ 不可以（与 Java synchronized 对比点）。
6. RWMutex 什么时候用？→ 读多写少；写优先。
7. 怎么发现数据竞争？→ go run -race / go test -race。
8. GMP 里 P 的作用？→ 本地队列、解耦 M 阻塞、限制并行度。
9. context 超时了 goroutine 会自动退出吗？→ 不会，要代码里检查 Done 才退出。
10. channel 关闭了还能读吗？→ 能，读完缓冲返回零值 + ok=false；for range 自动结束。
11. 怎么优雅关停服务？→ 监听信号 → cancel ctx → 等待 WaitGroup/errgroup 完成 → 退出。
12. 什么时候用 channel 什么时候用锁？→ 传递数据/协作用 channel；保护共享变量用锁。

# 01 · Go 基础八股

## 一、语言特性

- 静态强类型、编译型：编译成机器码直接运行，无虚拟机。
- 天生并发：goroutine + channel，语言层面支持。
- 自动垃圾回收；内存安全（没有指针算术）。
- 简单：没有继承/重载/泛型历史包袱（1.18 起有泛型），组合优于继承（结构体嵌入）。
- 包管理：go mod；`go.mod` 声明依赖，`go.sum` 校验。

### 值类型 vs 引用类型（必考）
- 值类型：int/float/bool/string/array/struct —— 赋值和传参是拷贝。
- 引用类型（传递时共享底层数据）：slice、map、channel、pointer、interface、func。
- 注意：Go 没有"引用"这个关键字，参数永远是值传递；slice/map 传的是"包含指针的结构体的拷贝"，所以改内容生效、改结构（append 扩容后的 cap 变化）不传回。

### 零值与 :=
- 每个变量有零值：int 0、string ""、bool false、slice/map/chan/interface/pointer nil。
- `:=` 声明并初始化；`var x int` 声明。
- 未使用的变量/导入会编译报错。

## 二、slice（必考中的必考）

### 底层结构
- slice 是"视图"：结构体 = 指向底层数组的指针 + len + cap。
```go
s := make([]int, 3, 5)   // len=3, cap=5，底层数组容量 5
```

### 扩容规则
- append 时 cap 不够则扩容：
  - 旧容量 < 256（1.18 前是 1024）：翻倍。
  - 更大时：约 1.25 倍（`newcap = old + old/4` 起步，配合内存对齐向上取整）。
- 扩容会分配新数组并拷贝，旧数组可能被共享 → 坑。

### 共享底层数组的坑（必答）
```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]        // b = [2 3]，cap 到 a 末尾
b[0] = 99          // a[1] 也变成 99（共享）
b = append(b, 6)   // 没触发扩容时写穿到 a[3]
```
- 防写穿：`copy` 到新 slice，或用 `s[start:end:end]`（三索引限制 cap）。

### 其他
- slice 的零值是 nil，nil slice 可以 append（直接分配新数组）。
- `len(s)`/`cap(s)` O(1)。
- range 遍历 slice 是拷贝元素：`for i, v := range s` 里改 v 不生效，要 `s[i] = ...`。

## 三、map（必考）

### 底层结构
- 哈希表：`hmap`，内部是 bucket 数组；每个 bucket 存 8 个键值对，溢出用 overflow 链表。
- key 必须可比较（可哈希）：基本类型、string、可比较的 struct/array；slice/map/func 不能做 key。
- 查找：hash → 定位 bucket → 逐个比较 key。
- 扩容：负载因子超过 6.5 或溢出桶过多时扩容（翻倍或等量整理），渐进式迁移。

### 并发安全（重点坑）
- map 不是并发安全的：并发写会 `fatal error: concurrent map writes`（直接崩，不是 panic）。
- 读写在并发时也要加锁（race detector 会报）。
- 并发场景用 `sync.Mutex + map` 或 `sync.Map`（读多写少、key 稳定、热点场景）。

### 其他
- 遍历顺序是随机的（语言刻意随机，别依赖顺序）。
- 读取不存在的 key 返回零值；区分"不存在"和"值为零"用 `v, ok := m[k]`。
- 删除用 delete(m, k)；make(map, n) 预分配容量减少扩容。
- map 是引用语义，传给函数改内容生效。

## 四、string 与 rune

- string 不可变（修改会复制），底层是只读字节数组，UTF-8 编码。
- 下标 s[i] 取的是字节，不是字符；中文 3 字节。
- rune = int32，一个 Unicode 码点；`for _, r := range s` 按 rune 遍历。
- 字符串拼接大量用 `strings.Builder` 或 `bytes.Buffer`，不要用 + 循环（每次分配）。

## 五、defer（必考，常手撕）

### 执行顺序
- defer 注册的函数在函数返回前执行，LIFO（后进先出）：
```go
defer fmt.Println(1)
defer fmt.Println(2)   // 输出 2 1
```

### 参数求值时机（重点）
```go
x := 1
defer fmt.Println(x)   // 立即求值，输出 1
x = 2                  // 不影响上面
```
- `defer func() { fmt.Println(x) }()` 闭包延迟读取，输出 2。

### defer 与 return 交互（高频）
```go
func f() (n int) {
    defer func() { n++ }()   // 能改返回值
    return 5                 // n = 5，然后 defer 改 n = 6，返回 6
}
```
- 顺序：先给返回值赋值（return 表达式求值）→ 执行 defer → 真正返回。
- 常用：defer 解锁、关闭文件、recover。

## 六、panic / recover

### 机制
- panic 使当前 goroutine 停止正常流程：沿调用栈逐层执行 defer，然后崩溃（打印堆栈）。
- recover() 能捕获 panic，但**必须在 defer 的函数里直接调用**才有效（recover 只对"当前 goroutine 的 panic"有效，且调用链上）。
```go
defer func() {
    if r := recover(); r != nil {
        fmt.Println("recovered", r)
    }
}()
```
- 不能跨 goroutine：A 里 panic，B 里 recover 无效。
- 什么时候用：程序入口兜底（HTTP handler 外层、main 的 goroutine 包装）；业务错误用 error 返回，不要用 panic。

## 七、错误处理

- Go 用返回值传错误（error 是内置接口），不用异常。
- Go 1.13+：`errors.Is(err, target)`（判断是否包含某错误）、`errors.As(err, &target)`（取出指定类型）、fmt.Errorf("%w", err) 包装。
- 常见坑：忽略错误 `_`、panic 当错误用、defer 里 Close 的错误不处理。

## 八、接口（必考）

### 隐式实现
- Go 接口是鸭子类型：类型实现接口所有方法即自动满足，无需 implements 关键字。
- 空接口 `interface{}` 可以接收任何值（1.18+ 可用 `any`）。

### 底层结构
- 接口由两部分组成：类型信息 + 值指针（iface 是接口+方法表，eface 是空接口）。

### 类型断言
```go
var i any = "hello"
s, ok := i.(string)     // ok 模式，安全
if !ok { ... }
switch v := i.(type) {  // 类型 switch
case string: ...
}
```

### 接口的 nil 坑（必答）
```go
var p *int = nil
var i any = p           // i != nil！接口有类型 (*int) 和值
if i == nil { ... }     // false
```
- 判断接口是否为 nil 要用反射或类型断言，不能直接 == nil。

### 结构体嵌入与方法集
- 嵌入实现"组合"：`type B struct { A }`，B 自动有 A 的字段和方法。
- 值接收者 vs 指针接收者：指针接收者的方法只能被指针调用（方法集规则）；值接收者的方法指针和值都能调。
- 一般规则：要么都用值接收者，要么都用指针接收者，保持一致。

## 九、常问追问

1. slice 扩容机制？→ 翻倍 → 1.25 倍，配合内存对齐。
2. slice 共享底层数组什么场景会出问题？→ append 不扩容写穿、扩容后旧引用无感知。
3. map 为什么并发写会崩？→ 内部哈希表无锁，runtime 检测到并发写直接 fatal。
4. defer 的执行顺序和参数求值？→ LIFO；参数立即求值，闭包延迟。
5. defer 能改返回值吗？→ 能，命名返回值时在 defer 里改。
6. recover 为什么必须在 defer 里？→ panic 后只有 defer 还在执行栈上。
7. 接口判断 nil 为什么坑？→ 接口 = 类型+值，typed nil 不等于 nil。
8. string 为什么不能改？→ 底层只读字节数组，修改需要转 []byte。
9. 为什么 range 修改 v 不影响原 slice？→ v 是副本。
10. 空 struct `struct{}{}` 有什么用？→ 零内存：map 做 Set、channel 做纯信号。

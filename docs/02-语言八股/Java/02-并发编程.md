# 02 · 并发编程

## 一、线程基础

### 创建方式
1. 继承 Thread
2. 实现 Runnable
3. 实现 Callable（有返回值，FutureTask 包装）
4. 线程池 ExecutorService（推荐，本质都是 Runnable/Callable）

### 生命周期状态
NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED
- BLOCKED：等 monitor 锁；WAITING：wait/join/park；TIMED_WAITING：sleep/wait(timeout)。
- 注意：Java 的 RUNNABLE 包含操作系统里的 Running + Ready。

### wait/sleep 区别
- wait 释放锁，必须持有锁时调用（同步块内）；sleep 不释放锁。
- wait 通常配 notify/notifyAll；notify 只唤醒一个，可能产生"假死"，一般用 notifyAll。

## 二、synchronized（必考）

### 用法
- 修饰实例方法：锁当前对象 this
- 修饰静态方法：锁 Class 对象
- 修饰代码块：锁指定对象（monitorenter/monitorexit 指令）

### 原理
- 每个对象头里有 Mark Word，记录锁状态；进入同步代码块时执行 monitorenter 获取 Monitor（管程/监视器锁），Monitor 依赖底层 Mutex（操作系统互斥量）。
- 可重入：同一个线程可重复获取，计数器 +1（锁的持有者是线程）。

### 锁升级（JDK 1.6 优化后）
无锁 → 偏向锁 → 轻量级锁 → 重量级锁（不可逆/可升级不可降级，偏向锁可批量撤销）
1. 偏向锁：只有一个线程反复进入，Mark Word 记录线程 ID，无竞争不开销。
2. 轻量级锁：有竞争但错开（自旋），CAS 把 Mark Word 拷到栈帧的 Lock Record；自旋超过阈值（或竞争激烈）升级。
3. 重量级锁：靠 Monitor + 操作系统 Mutex，线程阻塞唤醒，有用户态/内核态切换开销。

### 锁消除 / 锁粗化
- 逃逸分析发现对象不逃逸 → 消除锁；相邻同步块合并 → 锁粗化。

## 三、volatile

### 语义
1. 可见性：写 volatile 变量会强制刷新到主内存，读时从主内存读（缓存一致性协议，如 MESI）。
2. 有序性：加入内存屏障，禁止指令重排序。
3. 不保证原子性：i++ 是读-改-写三步，volatile 管不住，并发 i++ 仍会丢更新。

### 适用场景
- 状态标志位（如 boolean shutdownFlag）。
- 单例双重检查锁中修饰 instance（防半初始化对象）。
- volatile 不能替代锁做复合操作（计数、累加）。

### 与 synchronized 对比
- volatile 只能保证可见性/有序性，不能保证原子性；synchronized 三者都保证。
- volatile 无锁开销，轻量；synchronized 重量（但有优化）。

## 四、CAS 与原子类

### 原理
- Compare And Swap：内存值 = 期望值 时更新为新值，否则失败重试（自旋），依赖底层 CPU 指令（cmpxchg），Unsafe 提供。
- AtomicInteger 等原子类都用 CAS + volatile。

### 问题
1. ABA：值 A→B→A，CAS 察觉不到。解决：AtomicStampedReference / AtomicMarkableReference（带版本号）。
2. 自旋 CPU 开销：竞争激烈时一直空转（LongAdder 分散计数缓解）。
3. 只能保证单个变量原子性（多个变量用锁）。

## 五、ThreadLocal

### 原理
- 每个线程内部有 ThreadLocalMap（Entry 数组），key 是 ThreadLocal 的弱引用，value 强引用。
- 线程隔离：各线程读写自己的 Map，互不干扰。

### 内存泄漏
- key 是弱引用：线程存活时若 key 被 GC，value 仍被 ThreadLocalMap 强引用 → 泄漏。
- 解决：用完 `remove()`；线程池复用线程时尤其必须 remove（否则下个任务读到脏数据）。
- set/get 时会对 key 为 null 的 Entry 做清理（expungeStaleEntry），但不能依赖。

### 应用
- 传递用户上下文、DB 连接、事务；注意父子线程传值用 InheritableThreadLocal（线程池场景不可靠，可用 TransmittableThreadLocal）。

## 六、线程池（必考）

### 七大核心参数
1. corePoolSize 核心线程数
2. maximumPoolSize 最大线程数
3. keepAliveTime 非核心线程空闲存活时间
4. TimeUnit 时间单位
5. workQueue 任务队列（如 LinkedBlockingQueue/SynchronousQueue）
6. threadFactory 线程工厂
7. RejectedExecutionHandler 拒绝策略

### 执行流程
1. 线程数 < corePoolSize → 新建核心线程执行。
2. 达到核心数 → 任务进队列。
3. 队列满 → 新建非核心线程（最多到 maximumPoolSize）。
4. 线程数已达 max 且队列满 → 执行拒绝策略。

### 四种拒绝策略
- AbortPolicy：直接抛 RejectedExecutionException（默认）
- CallerRunsPolicy：调用者线程自己执行（降速）
- DiscardPolicy：静默丢弃
- DiscardOldestPolicy：丢弃队列最老任务再提交

### 核心线程数怎么设
- CPU 密集：N + 1；IO 密集：2N（或 N × (1 + 等待时间/计算时间)）。
- 实际还要看 QPS、单任务耗时、队列容量，先压测。

### 其他
- 为什么推荐用 Executors 会坑：newFixedThreadPool 用无界队列 LinkedBlockingQueue（任务无限堆积 OOM），newCachedThreadPool 最大线程数 Integer.MAX_VALUE（线程无限创建 OOM）。推荐 ThreadPoolExecutor 显式参数。
- 关闭：shutdown（等已提交任务完成）/ shutdownNow（中断）。
- 提交任务：execute（无返回值）/ submit（返回 Future，异常封装在 get 时抛）。
- 线程池参数动态调整：setCorePoolSize / setMaximumPoolSize。
- 监控：重写 beforeExecute/afterExecute，或看 activeCount/getQueue().size()。

## 七、AQS（ReentrantLock 的基石）

### 是什么
- AbstractQueuedSynchronizer：用 state（int，volatile）+ CLH 双向队列实现同步器，提供独占/共享两种模式，支持可重入、可中断、超时、公平/非公平。
- 很多同步工具基于它：ReentrantLock、Semaphore、CountDownLatch、ReentrantReadWriteLock。

### 加锁流程（非公平 ReentrantLock）
1. 先 CAS 抢 state 0→1，成功拿到锁，记录独占线程。
2. 失败 → 入队（CLH 尾插，CAS 更新 tail），前驱唤醒，自旋/阻塞（LockSupport.park）。
3. 释放：state 减到 0，唤醒队头后继。

### 公平锁 vs 非公平锁
- 公平：先入队先拿（hasQueuedPredecessors 检查），吞吐低。
- 非公平：新线程先直接 CAS 抢一次，抢不到再排队；吞吐高，可能饿死队头。

## 八、锁对比

| 维度 | synchronized | ReentrantLock |
| --- | --- | --- |
| 实现 | JVM 层面（monitor） | JDK 层面（AQS） |
| 锁升级 | 有（偏向/轻量/重量） | 无 |
| 可中断 | 否 | lockInterruptibly |
| 超时 | 否 | tryLock(timeout) |
| 公平性 | 非公平 | 可配公平/非公平 |
| 多个条件 | wait/notify | Condition（可多条件精确唤醒） |
| 用法 | 简单 | 需手动 unlock（finally） |

## 九、并发容器

- CopyOnWriteArrayList：写时复制（写锁+复制数组），读无锁，适合读多写极少。
- ConcurrentHashMap：见集合篇。
- BlockingQueue：ArrayBlockingQueue（有界，数组）/ LinkedBlockingQueue（可无界）/ SynchronousQueue（不存任务，直接交接）/ DelayQueue。
- ConcurrentLinkedQueue：无锁队列（CAS）。
- 倒计时/信号量：CountDownLatch（一次）、CyclicBarrier（可复用）、Semaphore（限流）。

## 十、常问追问

1. volatile 能保证 i++ 原子吗？为什么？→ 不能，读-改-写三步。
2. synchronized 锁升级过程？→ 偏向→轻量→重量。
3. 线程池提交一个任务后线程数怎么变化？→ 见流程，核心→队列→非核心→拒绝。
4. 线程池线程什么时候被回收？→ 非核心空闲超 keepAliveTime；allowCoreThreadTimeOut(true) 时核心也会。
5. ThreadLocal 为什么用弱引用？→ 防止 ThreadLocal 对象本身无法被回收；value 泄漏靠 remove。
6. CAS 的 ABA 怎么解决？→ 版本号。
7. AQS 为什么用双向队列？→ 方便取消节点和向前找未取消的前驱唤醒。
8. 怎么排查线程池满了？→ 看队列积压、拒绝策略日志、activeCount、压测调整参数。

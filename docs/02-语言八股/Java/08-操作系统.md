# 08 · 操作系统

## 一、进程 / 线程 / 协程

### 概念
- 进程：资源分配的基本单位，有独立地址空间（代码、数据、堆栈）。
- 线程：CPU 调度的基本单位，进程内共享地址空间，有独立栈和寄存器上下文。
- 协程：用户态轻量线程，由程序自己调度（如 Go goroutine、Java 虚拟线程），切换不经过内核，开销极小。

### 进程 vs 线程
- 通信：进程间靠 IPC（管道、消息队列、共享内存、信号量、Socket）；线程共享内存直接读写（需同步）。
- 开销：创建/切换线程远小于进程（进程切换要切地址空间，涉及 TLB 失效）。
- 崩溃影响：进程隔离，线程挂了整个进程挂。

### 进程状态
- 新建 → 就绪 → 运行 → 阻塞/等待 → 终止；运行时间片用完回就绪（抢占式）。

## 二、上下文切换

- CPU 保存当前任务的寄存器、PC、栈指针、页表等信息，加载下一个任务 → 开销主要在：保存/恢复寄存器、TLB 刷新（进程切换）、缓存失效、内核态切换。
- 线程切换比进程轻：不换地址空间。

## 三、死锁（必考）

### 四条件（同时满足才会死锁）
1. 互斥：资源一次只能一个进程用。
2. 持有并等待：持有资源又在等别的资源。
3. 不可剥夺：资源不能被强行拿走。
4. 循环等待：存在资源等待环。

### 预防（破坏任一条件）
- 破坏互斥：用读写锁/可共享资源（难）。
- 破坏持有并等待：一次性申请全部资源。
- 破坏不可剥夺：申请不到就释放已有。
- 破坏循环等待：资源按固定顺序申请（最常用）。

### 避免
- 银行家算法：分配前检查安全性，不安全则不分配。
- 检测与恢复：资源分配图检测环 → 杀死进程/回滚/资源抢占。

### 与数据库死锁的关系
- 数据库死锁也是这四条件：两个事务互相持有行锁等对方；InnoDB 死锁检测后回滚代价小的事务。

## 四、用户态与内核态

- 内核态：能执行特权指令、访问硬件和内核内存。
- 用户态：应用运行态，受保护，不能直接访问硬件。
- 切换：系统调用（read/write/fork）、中断、异常 → 用户态陷入内核态，有开销（保存上下文）。
- 为什么频繁系统调用慢：切换 + 拷贝数据（零拷贝 mmap/sendfile 优化）。

## 五、内存管理

### 虚拟内存
- 每个进程看到独立连续的虚拟地址空间，MMU 映射到物理内存（分页）。
- 好处：隔离、按需加载、超物理内存运行（换页）、简化链接。

### 分页与缺页
- 页表：虚拟页 → 物理页帧；多级页表减少内存占用；TLB 缓存页表加速。
- 缺页中断：访问未加载页 → 磁盘读入 → 更新页表 → 重执行指令。
- 页面置换算法：FIFO、LRU（最近最少使用）、LFU、Clock（近似 LRU）；最优 OPT（理论）。

### 内存碎片
- 内部碎片（页内剩余）、外部碎片（物理内存空洞）；伙伴系统 + slab 分配器解决。

## 六、进程间通信 IPC

- 管道（匿名/命名 FIFO）、消息队列、共享内存（最快，需同步）、信号量、信号 Signal、Socket。
- 选型：大数据量 → 共享内存；小消息解耦 → 消息队列；进程间事件通知 → 信号。

## 七、磁盘与 IO

- 机械盘顺序读快（连续扇区）、随机读慢（寻道）；SSD 无寻道，随机也好。
- 阻塞 IO / 非阻塞 IO / IO 多路复用（select/poll/epoll）/ 异步 IO（AIO）。
- epoll 优势：事件驱动、O(1) 查找就绪事件、无 fd 数量限制（vs select 1024）。
- 零拷贝：sendfile 减少用户态/内核态拷贝；Java NIO FileChannel.transferTo。

## 八、常问追问

1. 线程比进程快在哪？→ 不换地址空间，TLB/缓存少失效。
2. 死锁检测怎么实现？→ 资源分配图找环；数据库 InnoDB 的做法。
3. 虚拟内存为什么进程能"用"超过物理内存？→ 换页，页可以不在内存。
4. LRU 怎么实现？→ 哈希表 + 双向链表（LinkedHashMap accessOrder）。
5. 为什么线程切换比进程切换便宜？→ 页表/TLB/地址空间不换。
6. select/poll/epoll 区别？→ 轮询 vs 事件回调；fd 上限。
7. 写文件什么时候真正落盘？→ 写缓冲 + fsync；MySQL 的 redo log 也是同理（WAL）。
8. 上下文切换频繁会怎样？→ CPU 大量时间花在切换上（抖动 thrashing），吞吐下降。

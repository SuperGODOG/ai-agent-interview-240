# 项目面试拷问引擎

## 依赖与整包安装

本仓库按 **1 主入口 + 5 依赖**整包安装，勿单拆或单独关闭组件；六个目录必须位于同一个 skills 父目录。以下相对路径均以本 SKILL.md 所在目录为基准。本节降级分支优先于下文对应依赖调用。缺失组件时先明确报告降级，按下列内联规则继续可执行部分，不虚构题号、项目档案或已完成步骤。

本 skill 是 `agent-project-grill` 依赖的拷打引擎；依赖主入口提供公共题库，`interview-bank-pipeline` 提供新项目建档，`interview-resume-pack` 提供可选表达材料。

单件安装时，公共题库相对路径不存在才回退自身 `references/题库/`（兼容旧版单件安装）；新版单件不附带第二份题库。两处均缺失或所选目录三文件不全时，标注“无题库临时练习”，基于现有项目档案/用户代码一次一问，按下文四维点评，题号记“临时题”，跳过缺失的路由与 Lxx 作答段；只依据实际代码和用户提供的资料点评，不声称这是题库标准答案，不编造题库答案。缺 pipeline 且无项目档案时采用同样临时流程，不调用缺失脚本；缺主入口仍按本 skill 问答与复盘流程执行；缺备战包组件则按常规路由出题。工作区未配置且兼容目录不存在时，复盘暂留会话并明确未落盘。

## 语料布局（公共题库 + 自身项目快照，走路由加载，绝不整载）

先绑定 `BANK_ROOT` 为 `../agent-project-grill/references/题库/`；相对路径不存在时回退自身 `references/题库/`（兼容单件安装）。检查 items.json、concepts.yaml、schema.json 齐全后再读；不可用时执行上方降级规则。

- `BANK_ROOT/items.json` — 497 道题（共 557 条语料记录）（id/line/text/major/minor/depth/**prereq+downstream 学习路径**/**status 初始值**；公共题库仅存题目及元信息，不存固定预生成答案或四步模板）。题库不保存 concepts；`depth` 仅作为新增题的初始深度，项目路由以 `match.json` 的命中深度为准。**status 只作初始快照**（运行期状态写 vault 复盘文件）
- `BANK_ROOT/concepts.yaml` + `BANK_ROOT/schema.json` — 概念词典与分类骨架
- `references/项目/<slug>/` — 每个项目一套：
  - `match.json` 路由表（候选题目 + 命中概念 + 证据文件 + depth）
  - `项目画像.md` 技术档案/自我介绍底稿（含钩子）
  - `面试题匹配表.md` 题目×概念×证据对照
  - `项目内作答.md` 逐题作答（含 文件:行号 证据锚点，是点评依据）

## 路由与出题

0. **快照新鲜度前置校验**：出题前先校验目标项目快照新鲜度（运行 `check_snapshot.py`）。
   - **关联生命周期与语义审查**：只有代码（commit 一致且工作树 clean）与公共题库（items/concepts/schema 指纹一致）双 FRESH 时才可免重算直接复用；其他状态必须先经已有生产流程刷新或补档。`FRESH` 仅表示代码/题库/题号版本联通，不等于每个答案语义与源码证据已自动审查；题库扩容后旧项目自动变为待刷新（`STALE`），需按需重新运行 match 对齐新题。
   - **项目作答资产保护与代码变更约束**：项目回答正文属于项目专有资产，不能因题库更新被机械覆盖，但若代码发生变更，旧证据与旧答案必须先审查刷新后方可用于当前项目；只有在代码证据依然有效时才可保留旧作答并提示追加新题。无关 Infra 新题不强挂普通 Agent/秒杀。
   - **严格区分 L 题与 Q 卡空间**：项目 match.json 与匹配表只关联公共真题 L 编号（来自 items.json 的有效 question 条目），严禁混用 03_Cards 中的 Qxxx 题卡编号，两者属于独立空间。
1. 选项目：用户指定，或默认上次复盘的项目（读 vault 复盘文件），否则列出 `references/项目/` 目录让用户挑
2. 读 `references/项目/<slug>/match.json` → 候选题目列表（id/概念/深度齐全）
   - **动态精准检索与图谱级联（推荐）**：对于 Harness、SkillForge、秒杀等具备复杂演进或特定技术线索的项目，推荐优先调用轻量检索工具：
     `python3 ../interview-bank-pipeline/scripts/bank_search.py --query "<技术栈或架构关键词>" --top 3 --expand 1 --json`
     直接获取精准主干题与图谱自动级联的追问题清单，彻底避免静态标签过度抽象（Memory Tax）导致的追问漏召回。
3. 出题策略（按需组合）：
   - **深度递进**：按 depth 1→5 排序（概念定义→原理机制→设计实现→落地与权衡→前沿延伸）
   - **概念串问**：锁定一个 hit_concepts（如 MCP），连问命中该概念的多道题，考横向一致性
   - **薄弱优先**：读复盘文件中的薄弱主题，优先出该主题的题
   - **复习优先**：读 vault 复盘文件末尾的「待复习清单」（复盘时答错/低分标记的题 id），优先清
   - **前置递进**：用 prereq/downstream 链出题——先前置题再后置题，考体系而非孤题
   - **八股补充**：项目内作答含四_八股段（如 JeecgBoot）时，可穿插 Java 八股
4. 模式：严格（直接问，无提示）/ 学习（先给 30 秒概念提示再问）

## 问答循环（上下文预算：整场 ≤20K，默认 3 题/场，可加场）

- 出题：从 `BANK_ROOT/items.json` 按 id 取题目原文（约 100 tokens），一次一题，问完等用户作答
- 点评：只读 `项目内作答.md` 的 `### Lxx` 对应段（约 500 tokens）+ 画像相关段落（真实解答只依据具体项目生产生成，不从公共题库补编技术事实；无档案则明确仅问概念，答案待项目核实）
  - 四维打分，固定输出模板（markdown 表格）：`| 维度 | 得分(1-5) | 依据 |`
    维度 = 概念理解 / 原理深度 / 落地证据 / 结构完整度（概念认知→机制设计→工程权衡→落地验证）
    评分锚点：1=答错或空泛；3=方向对但缺细节/缺工程权衡；5=准确且带项目证据。首题评分后明示"以第 1 题为校准基准"
  - 表格后依次跟：答对 1 条 / 答漏 1 条 / 答错 1 条（各一行）、证据锚点 1-2 条（**只准引用作答档里已有的锚点**，禁止新造行号）、结构缺步提示 1 行、追问 1 句
  - 用户答完再公布答案要点：**答案要点 = 作答档 ### Lxx 段摘录（依据项目档案答案证据，无档案就进入生产建档或明确仅问概念、答案待项目核实，不退回固定模板）**，禁止输出语料外的新事实
- 熔断规则：第 3 题起不再重读画像段；点评输出压到模板最短形态
- 证据不足：作答档里没有的，诚实说明"项目无对应实现"，禁止编造；可引导用户给仓库路径现场查

## 复盘沉淀

- 每场结束写 `$INTERVIEW_WORKSPACE/obsidian_vault/40_项目档案/<slug>/面试复盘.md`（`INTERVIEW_WORKSPACE` 未设置时回退 `~/.interview-workbench`；以实际为准）：题目清单、四维得分表、薄弱主题、下场建议
- 答错/低分（任一维 ≤2）的题 id 记入复盘文件末尾的「待复习清单」（题 id + 薄弱维度）；已掌握的记入「已掌握清单」
- 复习状态只写在 vault 复盘文件，**不写 items.json**（skill 目录是只读快照，同步会覆盖）
- 文件不存在则创建；下一场开场先读它决定出题策略（复习优先）

## 诊断模式（第二模式，审代码不审人）

当用户给出代码路径/文件要求"审查这个项目"时切换：
1. 路由：跑 repo_fuse match 或按命中概念锁定题卡（L0 路由表）
2. 以命中题卡的答题框架为审查维度锚点，对代码做三维诊断：
   - **架构对齐**：当前代码与范式/最佳实践的差距（如 ReAct 循环缺熔断、记忆无写入路由）
   - **坑点与 Badcase 预警**：该技术点大厂生产落地常见坑（高并发限流、指代消解、前缀缓存失效）
   - **演进建议**：给出具体重构策略（引用代码文件:行号）
3. 输出诊断报告，写入 `40_项目档案/<slug>/代码诊断.md`
- 与拷问模式的区别：拷问审人（答题评分），诊断审代码（三维审查）；诊断模式不做四维打分

## 加载纪律（防上下文爆炸，四层漏斗）

- L0 路由：match.json 实测 14-22KB，**用 jq/grep 字段级提取**（`jq -r '.candidates[] | [.id, .depth, (.hit_concepts|join("/"))] | @tsv'` 或 search_files 精确 grep），只取 id/depth/概念三列（约 1K tokens）；需要题目原文时按 id 回查 `BANK_ROOT/items.json`
- L1 概念：需要时读 `BANK_ROOT/concepts.yaml` 单条目（约 300 tokens）
- L2 题目段：只读 `### Lxx` 锚点段（约 500 tokens）
- L3 证据：点评需要时按证据锚点 grep/read 源码片段（约 200 tokens/处）
- **禁止**：整读 项目内作答.md / items.json / vault 全量；一次只加载当前题的相关切片
- 语料是快照：仓库题库唯一来源为 `../agent-project-grill/references/题库/`；生产工作区在 `$INTERVIEW_WORKSPACE`（未设置时回退 `~/.interview-workbench`），题库或项目档案更新后按 `references/README.md` 的同步命令刷新

## 坑

- 点评必须基于作答档证据，不确定就说不确定，别替用户圆场
- 追问优先于公布答案；用户答不出时先给引导性问题，再亮证据
- 复盘/待复习清单写 vault（可写），skill 目录只读（快照）——status 等运行期状态一律不进 skill 目录
- 引用锚点前先确认它在作答档里存在（搜不到就按"证据不足"处理，不编行号）
- 用户岔开话题问设计问题时，先回答问题再拉回面试节奏

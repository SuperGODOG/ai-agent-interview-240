# 面试备战包生成（漏斗稿 + 深钻点 + 防守材料）

一句话：从已建档项目档案生成"漏斗式表达"全套面试材料。当前加载本 skill 的 agent 是**编排者**；可选委派其他生成 agent，最终由编排者执行证据门防编造。
与面试三件套的关系：interview-bank-pipeline 管建档（生产端）→ 本 skill 管表达材料（生产端，拷打的**软前置**）→ agent-project-grill 管拷打（消费端：备战包缺失时提示生成但不阻塞；深钻点 L3 与不会题清单为优先出题源；复盘暴露的薄弱点以「备战包修订建议」回流复盘文件，积累 ≥3 条触发重生成）。

## 依赖与整包安装

本仓库按 **1 主入口 + 5 依赖**整包安装，勿单拆或单独关闭组件；六个目录必须位于同一个 skills 父目录。以下相对路径均以本 SKILL.md 所在目录为基准。本节降级分支优先于下文对应依赖调用。缺失组件时先明确报告降级，按下列内联规则继续可执行部分，不虚构题号、项目档案或已完成步骤。

本 skill 是 `agent-project-grill` 依赖的表达材料生产端，使用 `interview-bank-pipeline` 建档产物与 `project-mock-interview` 项目快照。

单件安装缺主入口时，仍按本 skill 分批生成与证据门执行。缺引擎时，以工作区 `repos_cache/<slug>/match.json` 加 `obsidian_vault/40_项目档案/<slug>/` 中的项目画像、项目内作答替代阶段 0 的快照三件套，必须逐一验证。缺 pipeline 但已有完整档案与源码时继续；必要档案/源码缺失则只列出待补清单，停止生成正式备战包，不伪造档案或绕过证据门。缺 grilling/audit 不影响出稿。

## 产出物六件套 + 总览

阶段 0 解析 `<workspace>` 后，输出到 `<workspace>/obsidian_vault/40_项目档案/<slug>/备战包/`：

1. `漏斗稿.md` — 30s / 3min / 10min 三版
2. `深钻点-<名称>.md` × 2-3 — 每点五层拆解，附证据锚点
3. `DHR卡.md` — 核心场景 Detection→Handling→Recovery
4. `不会题.md` — 极限题防守模板库
5. `组合failure.md` — 跨模块 worst-case 推演
6. `简历bullet.md` — 本人贡献已证实时为 3-5 条主 bullet + 每条数字出处；第三方/学习谈资项目走下方不适用分支

另生成 `README.md` 总览页（产物索引 + 完整性状态 + 拍板记录 + 不深钻清单 + 待补清单）；README 是索引，不计入六类正文产物。

## 0. 前置检查

1. **解析工作区**：`INTERVIEW_WORKSPACE` 非空时绑定为 `<workspace>`；未设置时，仅当兼容目录 `$HOME/.interview-workbench` 已存在才绑定它。两者都不可用则停止写入，提示先按 interview-bank-pipeline「跨平台部署」设置 `INTERVIEW_WORKSPACE`；禁止把空变量拼成 `/obsidian_vault/...`，也禁止自动创建兼容目录。
2. **校验建档三件套与快照版本新鲜度**：
   - 定位 slug（`owner__repo`），从当前 runtime 已加载的 project-mock-interview skill 根定位 `references/项目/<slug>/`，检查 `match.json`、`项目画像.md`、`项目内作答.md` 是否存在可读；
   - **快照新鲜度核验（关键防线）**：运行 `python3 <interview-bank-pipeline>/scripts/check_snapshot.py <repo-root>`：
     - 若返回 `STALE`（快照代码落后或公共题库已扩容未对齐）或 `LEGACY_UNTRACKED`（旧版无版本快照）：**严禁直接出稿！** 必须先通过 interview-bank-pipeline 重新建档并刷新快照。防止基于已过时的旧代码或旧题库生成过时的漏斗稿、深钻点和简历 bullet；
     - 若返回 `MISSING`：停止生成，先触发 interview-bank-pipeline 阶段三建档；
     - 若返回 `FRESH` 或 `DIRTY_WORKTREE`：快照与代码/题库双向对齐，安全通过，继续后续流程。
3. **解析源码根**：优先使用用户明确给出的仓库目录，否则检查 `<workspace>/repos_cache/<slug>/`，绑定为 `<repo-root>`；目录不存在则停止生成并报告缺失，因为代码锚点无法过证据门。
4. **读取运行期输入**：`<workspace>/obsidian_vault/40_项目档案/<slug>/学习卡.md`、`面试复盘.md` 存在才抽取未完成学习卡、薄弱维度及未处理的「备战包修订建议」，不存在按空输入继续。用户提供了既有简历终稿路径时只读相关项目 bullet；未提供则跳过冲突比对，并在 README 标注「未核对既有简历」。
5. **确认事实归属**：项目画像若标记为第三方项目/学习谈资，后续不得把仓库能力写成本人贡献；没有本人贡献证据时，`简历bullet.md` 明示「不适用：仅学习谈资」，不凑 3-5 条。
6. **准备目标目录**：确认 `<workspace>/obsidian_vault/40_项目档案/<slug>/` 可写，再创建或复用其 `备战包/` 子目录；已有备战包只在本次明确重生成时按批更新，禁止改动项目档案的其他文件（阶段 4 勾选已吸收建议除外）。

## 1. 深钻点选定（唯一用户拍板点）

判定标准 = 证据链三要素至少占二：
- A 真实数字（怎么测出来的）
- B 踩坑故事（怎么发现→定位→修→现在怎么防）
- C 被否决的替代方案（为什么不用 X）

- 从建档三件套按下方切片法盘点每个候选模块的三要素存量，存量最厚的 2-3 个为默认
- 每个候选还必须至少有 1 个能在 `<repo-root>` 规范化并通过 evidence_gate 的仓库相对锚点；只有 A/B/C、没有可校验锚点的不算合格
- 合格候选少于 2 个 → 不降标准、不凑数，停在本阶段并报告还缺哪些数字/踩坑/否决方案；不得进入生成阶段
- 有用户在场 → 列出候选、证据存量与首选项，请用户拍板；用户不在 → 按默认走并在 README 标注"可换"
- 同时确定**不深钻清单**并放入每个生成任务包，最终完整写入 README；漏斗稿 30s 版绝不出现这些模块名（排雷——没准备的东西一个字不出现，信息差是最大资产）

## 2. 分批生成（agy 可选）

任务包由编排者组装。`≤8K tokens` 指单次派发中生成 worker 可见的输入（生成原则 + 本批模板 + 拍板/排雷清单 + 输入切片 + 必要会话历史），不含本轮模型输出；能读取 runtime token 计数时以实测为准。没有计数器时，把完整任务包序列化为 UTF-8 后用运行时字节计数（Unix 可用 `wc -c`）并限制在 4,000 bytes 内；记录为「字节代理通过、精确 token 未验证」，仍超长就继续拆批。

- 每批任务包必须自包含：目标目录与文件名、选定深钻点、不深钻清单、"生成原则"、本批对应的完整"模板硬结构"、证据格式、相关输入切片；不能假定生成 worker 已读本 SKILL
- 固定分批：① `漏斗稿.md`；② 每个 `深钻点-<名称>.md` 各一批；③ `DHR卡.md` + `不会题.md` + `组合failure.md`；④ `简历bullet.md` + `README.md` 收口。默认禁止一轮生成全套；每批直接写目标文件
- 裁剪顺序：先保留生成原则与本批模板，再保留拍板/排雷清单、候选路由摘要、画像命中段、必要 Lxx 作答段、锚点附近代码；超限先删非命中背景，仍超限则按一个目标文件或一个 Lxx/证据子段再拆，禁止截断证据段
- 同一文件被拆成多个子批时采用增量协议：首子批先创建完整模板骨架并只填本批有证据的槽位；后续子批只更新任务包点名的标题/层级，必须保留其他内容，禁止整文件覆盖；最后增加一个该文件收口子批，负责合并去重、补齐结构、清除无证据断言，再进入证据门
- 可选委派：只有当前 runtime 能发现并成功调用 agy 时才委派；先看实际 `agy --help`，不得假定存在 agy skill 或使用未经验证的短参数。续最近会话只用于同一文件的局部返修；指定会话 ID 时仅使用该版本帮助中明确支持的参数
- 降级闭环：agy 未安装、无权限、认证/网络失败或调用报错时，由**当前编排者**按相同批次、模板和证据标准直接出稿，并在 README 标注「降级出稿」；谁出稿谁负责按 FAIL 清单只修对应文件/段落
- 跨批默认开新会话，只传本批自包含任务包；同一批返修若会话历史令可见输入超限，也开新会话，仅传目标文件路径、FAIL 清单与必要证据切片，不重灌其他产物正文

切片定位必须按以下顺序执行，禁止整载档案：

1. `match.json`：用结构化 JSON 读取（runtime 能力、Python 标准库或可用的 `jq`），只保留 `candidates` 中的 `id/depth/hit_concepts/evidence`。分两遍：选点前按 `hit_concepts` 分组形成候选模块并逐组筛 Lxx；拍板后只保留已选模块的 Lxx 供生成
2. `项目画像.md`：先用可用的文本搜索建立标题索引（优先 `rg -n '^#{1,3} '`；没有 `rg` 时用 Python 标准库或等价工具），只取命中「架构/自我介绍/钩子/追问/框架给的 vs 我设计的」的相关标题段，读到下一同级标题为止
3. `项目内作答.md`：用 `^### Lxx(?: |$)` 定位选中的题段，只读到下一个 `^### L[0-9]+` 或 `^## `；每批只装当前目标所需 Lxx
4. 代码：仅按作答段已有 `路径:行号` 到 `<repo-root>` 读取锚点附近小片段。若原锚点只有 basename/不完整路径且 `<repo-root>/<路径>` 不存在，用文件清单做**精确后缀匹配**（优先 `rg --files <repo-root>`，无 `rg` 用 runtime 文件枚举）；唯一命中才改写为完整仓库相对路径，零命中或多命中均标 `[待补: 锚点歧义]`，禁止猜选。此处搜索只用于解析已有锚点，不得据此断言某能力全仓不存在。学习卡只取未勾选项，复盘只取薄弱项与未勾选的备战包修订建议

## 3. 证据门（编排者校验，谁出稿谁返修）

1. **锚点校验与版本对账**：对六类正文的每个实际文件逐一执行 `python3 <本skill目录>/scripts/evidence_gate.py <产物文件> <repo-root>`；路径:行号锚点逐一 exists，悬空即 FAIL。脚本会自动检测关联的 `snapshot_meta.json` 并比对仓库 HEAD commit 是否一致，若检测到代码版本漂移将输出警示（支持 `--strict-commit` 严格拦截）。两个内容特例改走人工门而不运行脚本：①阶段 0 判定为第三方/学习谈资且无本人贡献的 `简历bullet.md` 只能写固定不适用声明，编排者对照 `项目画像.md` 核验事实归属；②仅当 `不会题.md` 每一题都被 `项目内作答.md` 或画像明确标为无直接实现、且均无邻近对应物时，编排者逐题核对该语义边界并在 README 记录「不会题：人工边界门通过」。不满足特例条件却零锚点仍为 FAIL，禁止拿无关文件凑锚点。README 是索引，也豁免该脚本，只校验它列出的相对链接均存在
2. **数字红线**：全部正文中的每个项目数字必须有档案/作答档/代码出处；找不到 → 标 `[待补: 指标/口径]` 或删除，禁止保留无出处数字
3. **结构完整**：`漏斗稿.md`、2-3 个深钻点文件、`DHR卡.md`、`不会题.md`、`组合failure.md`、`简历bullet.md` 六类正文及 `README.md` 齐全；每深钻点五层齐全；每不会题含四步；README 的「完整性状态」只有在所有检查 PASS 后才写「完整」
4. **名词密度红线**：不会题答案里方案描述用功能性描述（专有名词降级），钩子名词只允许出现在深钻点覆盖范围内
5. **排雷校验**：30s 版中不深钻清单的模块名零出现
6. **返修闭环**：任一 FAIL → 只把失败文件/段落和必要证据切片交回原出稿者；修后重跑该文件。所有文件 PASS 前不得交付，也不得把 README 状态写成「完整」

## 4. 交付与回注

- README.md 总览页：**版本快照元数据（Commit Hash + 分支 + 生成时间）** + 完整性状态 + 产物索引 + 深钻点拍板记录 + 不深钻清单 + 是否降级出稿 + [待补]数字清单 + 已吸收修订建议
- 回注 agent-project-grill：深钻点 L3 层问题作为下一场拷打出题源（出题策略：备战包优先）
- 简历bullet 红线：阶段 0 已加载用户既有简历终稿时，冲突处以终稿为准（事实红线零回退），只增不改；未加载时不得声称已核对
- 全套 PASS 后，把本轮实际吸收的复盘条目从 `- [ ] 备战包修订建议：...` 改为 `- [x] ...`；未吸收项保持未勾选，避免重复触发重生成

## 生成原则（写进每次任务包顶部）

1. 漏斗 = 画地图，把面试官引进预设战场；30s 版是问题空间划定，不是项目总结
2. 深钻点 = 证据链三要素至少占二的 2-3 个点，其余模块只保"职责/接口/为什么存在/基本实现/failure mode"
3. 不会题 = 主动收刀：名词降级 + 具体数字划界；绝不"没考虑过"，绝不抛接不住的名词
4. 单模块 L3 之外必配组合 failure（模块A故障×模块B失效的传播链与断路设计）
5. 一切数字有出处，编造 = 打回（历史教训：agy 按八股"应该的样子"编造项目细节）

## 模板硬结构（所有出稿路径必须遵守）

- **漏斗稿 30s**：一个痛点 → 两分法拆解（如"选得准 / 加载得省"）→ 闭环拍点（评估体系）。禁模块名词罗列
- **漏斗稿 3min**：架构文字版 + 数据流 + 两分法各一段方案 + 为什么是这个拆法
- **漏斗稿 10min**：与已拍板深钻点一一对应的 2-3 个核心设计 × 每个（背景 / 方案 / 三要素证据链 / known limitation / 至少一个规范化后的 `代码路径:行号`）；整个 `漏斗稿.md` 不得零锚点
- **深钻点五层**：L1 为什么存在（含否决方案）/ L2 机制 + 参数怎么定 / L3 证据追问题清单（每条含问题 + 答案要点 + 怎么知道有效 + 测试集怎么构造 + 锚点）/ L4 失效边界 + 反事实（什么时候挂、替代解释）/ L5 规模外推与演进（规模×N 怎么办、下一步验证）；每层缺证据写 `[待补]`，文件末附至少一个规范化后的 `代码路径:行号` 锚点
- **DHR**：每个深钻点至少 1 个场景；场景 → Detection（信号/监控/日志）→ Handling（降级/兜底）→ Recovery（自愈/人工/数据修复）→ 证据锚点
- **不会题四步**：从不深钻模块/无直接实现的高风险候选中选 3-5 题；每题按数字划界（benchmark 在 X 规模，未知则 `[待补]`）→ 拆关注点（延迟/召回/成本）→ 功能性方案（名词降级）→ 验证计划（先测什么指标确认瓶颈）→ 证据边界。无直接实现时明确写「项目无直接实现，以下是验证计划」，有邻近对应物才附其规范化锚点；除满足证据门第 1 条的全无实现人工门特例外，整个 `不会题.md` 至少保留一个可由脚本验证的仓库代码/文档锚点
- **组合failure**：从已选深钻点中任选两个，至少写 1 组；A×B 组合 → 传播链 → 最坏状态 → 检测点 → 断路设计 → 证据锚点
- **简历bullet**：自研/本人贡献已证实时写 3-5 条，动词开头 + 机制一句话 + 数字结果（无已验证数字时允许「结果描述 + `[待补: 指标/口径]`」）；每条附 `代码路径:行号`。第三方/学习谈资且无本人贡献证据时只写固定不适用声明，事实归属由编排者按证据门特例人工核验
- **README**：`完整性状态: 完整|未完成` + 六类正文相对链接 + 深钻点拍板记录 + 完整不深钻清单 + 出稿路径（委派/降级）+ `[待补]` 清单 + 已吸收修订建议 + 简历终稿核对状态

## 跨 agent 部署

- 本 skill 属 interview-mock-skill 套件仓库，与其他 skill 同仓库维护；安装到当前 runtime 支持且能发现的 skill 目录，并确认 interview-bank-pipeline 与 project-mock-interview 也可发现。`.cc-switch` 只可作为某台机器的可选汇聚层，不是运行前提
- 数据路径纪律同套件：所有读写都使用阶段 0 已绑定的 `<workspace>`；skill 目录只读。兼容目录只在已存在时启用，跨平台/新设备必须显式设置 `INTERVIEW_WORKSPACE`

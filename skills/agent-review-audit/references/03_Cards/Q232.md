# Q232: 事件循环（Event Loop）通常是一个死循环，为什么它在没有事件处理时不会导致CPU占用率过高或系统卡死？底层的休眠与唤醒机制是怎样的？

> [!SUCCESS] 通用参考与审查要点
> - **核心考点与概念权衡**: 事件循环在无事件就绪时不占用 CPU 的底层休眠唤醒机制（epoll/kqueue 内核挂起）。
> - **代码与证据关注点**: 检查底层系统调用等待代码（如 epoll_wait 传入超时时间或管道通知唤醒）。
> - **边界与追问方向**: 虚假唤醒（Spurious Wakeup）防范、多线程环境下向 Looper 线程安全投递事件的唤醒机制。

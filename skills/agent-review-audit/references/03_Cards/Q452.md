# Q452: MoE 前向数据流、Router Replay 消费机制与 EP/TP 并行通信设计：一个 Token 在 MoE 中的完整前向链路是什么？Router Replay 记录的路由信息在训练侧哪一环节恢复消费？EP 与 TP 的逻辑切分轴与通信实现有何不同？

> [!QUESTION] 问题描述
> MoE 前向数据流、Router Replay 与并行通信：一个 Token 进入混合专家模型（MoE）后的完整前向流程是什么（Gate 选路、Top-K 分配、Token Dispatch、专家计算与 Combine 汇聚）？在 Rollout 阶段记录的 Token、Layer、Top-K 路由（Router Replay）信息是在训练侧哪个具体环节被恢复与消费的？分布式训练中 Expert Parallelism (EP) 与 Tensor Parallelism (TP) 作为逻辑切分轴，其进程分组与实际通信实现（如 All-to-All、AllGather、Reduce-Scatter 等）有何不同？

> [!SUCCESS] 通用参考与审查要点
> - **逻辑轴与数据流**: EP 与 TP 均为张量/模型切分的逻辑分区轴，可依集群拓扑在机内或跨机部署；EP dispatch 常见 All-to-All 或 AllGather，TP 常见 All-Reduce 或 ReduceScatter+AllGather。
> - **Router Replay 消费机制**: 在各层 MoE 门控与 dispatch 路径中恢复消费路由记录，确保前向计算与梯度传播严格对齐采样路径，而非仅在 loss 阶段单点使用。
> - **审查与追问**: 检查路由记录（专家 ID、Top-K 权重等）的保存与消费实现；追问负载不均衡、Token 丢弃与跨节点通信瓶颈治理。
